# UV 與 Python 依賴管理指南

本文件旨在為 `VOL-FUTURE-LAB` 專案提供一套清晰的 Python 版本與依賴管理策略，確保開發環境的穩定性、可重現性與未來擴展性。

---

## 1. Python 支援版本

-   **主要開發版本**：`Python 3.12`
-   **最低支援版本**：`Python 3.10`

所有新功能開發應優先以 `3.12` 為基礎。若未來 `uv` 或核心套件（如 `duckdb`, `pandas`）宣布停止支援 `3.10`，我們將正式棄用該版本。

---

## 2. CI 測試矩陣建議

為了確保程式碼在不同環境下的相容性，持續整合（CI）流程應建立以下測試矩陣：

| 作業系統 | Python 版本 | 測試目標                               |
| :------- | :---------- | :------------------------------------- |
| `ubuntu-latest`  | `3.12`        | **核心功能**：確保主要開發環境穩定       |
| `ubuntu-latest`  | `3.10`        | **向下相容**：確保程式碼在最低支援版本正常 |
| `windows-latest` | `3.12`        | **跨平台**：確保在 Windows 環境下功能無誤  |
| `macos-latest`   | `3.12`        | **跨平台**：確保在 macOS 環境下功能無誤  |

此矩陣旨在平衡測試的全面性與 CI 資源的消耗。

---

## 3. 如何處理套件不相容

當遇到套件版本衝突或與特定 Python 版本不相容時，應遵循以下步驟：

1.  **鎖定問題**：
    *   首先確認是哪個套件的哪個版本造成問題。
    *   查閱該套件的官方文件或 `PyPI` 頁面，確認其支援的 Python 版本範圍。

2.  **尋找替代方案**：
    *   **升級/降級套件**：嘗試尋找一個既能滿足功能需求，又與現有環境相容的套件版本。
    *   **尋找替代套件**：如果無法找到相容版本，研究是否有功能相似的替代套件。

3.  **修改程式碼**：
    *   若不相容問題來自於程式碼使用了已被棄用的 API，應優先修改程式碼以適應新版套件。

4.  **記錄決策**：
    *   所有關於版本鎖定、更換套件的決策，都必須在 `log.md` 中詳細記錄原因與過程，以便團隊成員追蹤。

## 4. 何時升級 Python 的政策

專案的 Python 主要版本應保持積極但穩健的升級策略。

### 4.1 升級時機

-   **安全性更新**：當前使用的 Python 版本出現重大安全漏洞時，必須立即規劃升級。
-   **核心依賴要求**：當 `pandas`, `duckdb` 或 `pyarrow` 等核心套件的未來版本宣布將不再支援我們當前的 Python 版本時，應提前規劃升級。
-   **性能或功能需求**：當新版 Python 提供顯著的性能改進（例如 `Python 3.11` 的 `TaskGroup`）或對專案有益的新語法時，可啟動升級評估。

### 4.2 升級流程

1.  **建立測試分支**：在獨立的 `feature/upgrade-python-X.XX` 分支中進行升級。
2.  **修改環境設定**：更新 `.python-version` 與 `requirements.txt` / `pyproject.toml`。
3.  **執行完整測試**：在 CI 環境中，針對新版本執行完整的測試矩陣。
4.  **程式碼調整**：修復所有因版本升級造成的程式碼不相容問題。
5.  **合併與部署**：測試完全通過後，將升級分支合併回主線。
